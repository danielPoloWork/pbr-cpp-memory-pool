## 1. 目标与业务背景

许多高性能系统（例如图形引擎、金融交易服务器、数据库）都受到内存碎片化，以及频繁调用 `malloc`/`free` 或 `new`/`delete` 所产生开销的影响。
本组件旨在提供一个**自定义内存分配器**（内存池，Memory Pool），它预先分配一块连续的内存，以常数时间 $O(1)$ 管理固定大小块的分配与释放，且零外部碎片。

---

## 2. 功能需求

- **初始化：** 系统必须能够预先分配一块连续的内存池，并指定块大小（`block_size`）和最大块数量（`block_count`）。
- **分配（$O(1)$）：** 必须以常数时间返回指向池中某个空闲块的指针。如果池已耗尽，必须返回 `NULL`（或在 C++ 中抛出异常），或者在配置为动态模式时申请一块新的连续内存。
- **释放（$O(1)$）：** 必须以常数时间将先前分配的块重新标记为可用，而不立即将其归还给操作系统。
- **线程安全：** 池必须支持多个线程的并发访问而不发生内存损坏（可选，或可通过编译期宏进行配置，以最大化单线程性能）。

---

## 3. 非功能需求

- **无内存泄漏：** 当池被销毁时，所有预先分配的内存都必须归还给操作系统。
- **最小内存开销：** 用于跟踪空闲块的内部元数据（例如通过内部链表或位掩码）的使用必须最小化。
- **兼容性：** 以标准 ANSI C（或 C++17）编写，无外部依赖。

---

## 4. 逻辑架构与算法（Free List）

池使用一个内嵌于块自身的隐式 **Free List**（空闲链表）来管理空闲内存。当一个块空闲时，它的前若干字节被用于存储指向下一个空闲块的指针。这使得未使用块的元数据开销归零。

```text
+-------------------------------------------------------------------+
|                        内存池 (Memory Pool)                        |
+-------------------------------------------------------------------+
| [块 1（空闲）]   -> 保存指向「块 2」的指针
| [块 2（已分配）] -> 保存用户数据
| [块 3（空闲）]   -> 保存指向「块 4」的指针
| [块 4（空闲）]   -> 保存 NULL（链表结束）
+-------------------------------------------------------------------+
```

---

## 5. API / 公共接口（C）

```c
typedef struct memory_pool memory_pool_t;

// 初始化内存池
memory_pool_t* memory_pool_create(size_t block_size, size_t block_count);

// 从池中分配一个块（O(1)）
void* memory_pool_alloc(memory_pool_t* pool);

// 将一个块释放回池中（O(1)）
void memory_pool_free(memory_pool_t* pool, void* block);

// 销毁池，将所有内存归还给操作系统
void memory_pool_destroy(memory_pool_t* pool);
```

## 6. 验证与测试策略

1. **正确性测试：** 分配所有块直到耗尽；验证在空输入或池外指针情况下的行为。
2. **泄漏验证（Valgrind）：**
    - 验证命令：

        ```bash
        gcc -g -O0 test_pool.c memory_pool.c -o test_pool
        valgrind --leak-check=full --show-leak-kinds=all ./test_pool
        ```

    - **成功标准：** `ERROR SUMMARY: 0 errors from 0 contexts`。
3. **性能基准测试：** 在 1,000,000 次迭代的循环中，将 `memory_pool_alloc`/`free` 与标准 `malloc`/`free` 的执行时间进行对比。
