## 1. 目的とビジネス背景

多くの高性能システム（例：グラフィックスエンジン、金融取引サーバ、データベース）は、メモリの断片化や、`malloc`/`free` あるいは `new`/`delete` の頻繁な呼び出しによって生じるオーバーヘッドに悩まされます。
本コンポーネントは、連続したメモリブロックを事前確保し、固定サイズのブロックの確保と解放を定数時間 $O(1)$ で、外部断片化ゼロで扱う**カスタムメモリアロケータ**（メモリプール、Memory Pool）を提供することを目的とします。

---

## 2. 機能要件

- **初期化：** システムは、ブロックサイズ（`block_size`）と最大ブロック数（`block_count`）を指定して、連続したメモリプールを事前確保できなければなりません。
- **確保（$O(1)$）：** プール内の空きブロックへのポインタを定数時間で返さなければなりません。プールが枯渇した場合は `NULL` を返す（または C++ では例外を送出する）か、動的モードに設定されていれば新しい連続ブロックを要求しなければなりません。
- **解放（$O(1)$）：** 以前に確保したブロックを、オペレーティングシステムに即座に返却することなく、定数時間で再び利用可能としてマークしなければなりません。
- **スレッドセーフ：** プールは複数スレッドからの並行アクセスをメモリ破壊なしにサポートしなければなりません（任意、または単一スレッド性能を最大化するためコンパイル時マクロで設定可能）。

---

## 3. 非機能要件

- **メモリリークなし：** プールの破棄時に、事前確保した全メモリをオペレーティングシステムに返却しなければなりません。
- **最小限のメモリオーバーヘッド：** 空きブロックを追跡するための内部メタデータ（例：内部連結リストやビットマスク）の使用は最小限でなければなりません。
- **互換性：** 外部依存のない標準 ANSI C（または C++17）で記述します。

---

## 4. 論理アーキテクチャとアルゴリズム（Free List）

プールは、ブロック自身の内部に埋め込まれた暗黙の **Free List**（空きリスト）を用いて空きメモリを管理します。ブロックが空いているとき、その先頭の数バイトが次の空きブロックへのポインタの格納に使われます。これにより未使用ブロックのメタデータオーバーヘッドがゼロになります。

```text
+-------------------------------------------------------------------+
|                       メモリプール (Memory Pool)                   |
+-------------------------------------------------------------------+
| [ブロック 1（空き）]   -> 「ブロック 2」への next-free ポインタ
| [ブロック 2（使用中）] -> ユーザーデータ
| [ブロック 3（空き）]   -> 「ブロック 4」への next-free ポインタ
| [ブロック 4（空き）]   -> NULL（空きリストの終端）
+-------------------------------------------------------------------+
```

---

## 5. API / 公開インターフェース（C）

```c
typedef struct memory_pool memory_pool_t;

// メモリプールを初期化する
memory_pool_t* memory_pool_create(size_t block_size, size_t block_count);

// プールからブロックを確保する（O(1)）
void* memory_pool_alloc(memory_pool_t* pool);

// ブロックをプールに解放する（O(1)）
void memory_pool_free(memory_pool_t* pool, void* block);

// プールを破棄し、全メモリをオペレーティングシステムに返却する
void memory_pool_destroy(memory_pool_t* pool);
```

## 6. 検証とテスト戦略

1. **正当性テスト：** 枯渇するまで全ブロックを確保する。null 入力やプール外のポインタに対する挙動を検証する。
2. **リーク検証（Valgrind）：**
    - 検証コマンド：

        ```bash
        gcc -g -O0 test_pool.c memory_pool.c -o test_pool
        valgrind --leak-check=full --show-leak-kinds=all ./test_pool
        ```

    - **成功基準：** `ERROR SUMMARY: 0 errors from 0 contexts`。
3. **性能ベンチマーク：** 1,000,000 回の反復ループで、`memory_pool_alloc`/`free` と標準の `malloc`/`free` の実行時間を比較する。
