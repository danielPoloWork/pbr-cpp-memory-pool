# Benchmark — v0.5.0 dynamic-growth amortized cost (Windows / MSVC / x64)

Growth-scenario benchmark for **Milestone 5.4**. Methodology: [ADR-0014](../adr/0014-microbenchmark-methodology-pool-vs-malloc.md); the **growth** scenario (M5.4) bulk-allocates `iterations` blocks into a *dynamic* pool that starts at 256 blocks and grows geometrically (factor 2) during the run, so the per-op median folds in the periodic chunk allocations. Produced by `pool_vs_malloc_bench --scenario growth` (NONE policy).

## Host

| Field | Value |
|-------|-------|
| CPU | Intel Core i5-6600K (Skylake) @ 3.5 GHz |
| OS | Windows 10 Pro 19045 |
| Compiler | MSVC 19.51, Release |
| Config | `iterations=1000000 repeats=10 block_size=64`, dynamic initial 256, factor 2 |

## Result (median ns/op, bulk alloc)

| Scenario | pool | `malloc` | malloc / pool |
|----------|-----:|---------:|--------------:|
| **growth** (dynamic, 256 → 1,000,000) | 55.2 | 108.1 | **1.96 ×** |
| bulk (fixed, pre-sized to 1,000,000) — for reference¹ | ~6.3 | ~71 | ~11 × |

¹ The fixed-mode `bulk` numbers are from the v0.4.0 report ([`v0.4.0-windows-msvc-x64-threading.md`](v0.4.0-windows-msvc-x64-threading.md)) on the same host.

## Reading it

- **A growing pool is still ~2× faster than `malloc`** on amortized bulk allocation, even though it pays for ~12 geometric chunk acquisitions (256 → 512 → … → ~1,000,000) along the way.
- **Growth is not free**: amortized alloc rises from ~6 ns/op (a pre-sized fixed pool) to ~55 ns/op when the pool must grow from a small initial capacity. The cost is the periodic `::operator new` for each new chunk plus initialising its free list — paid `O(log N)` times (geometric, ADR-0022 §2), then amortized across all allocations.
- **Takeaway:** size the pool up front when the working-set size is known (the 11× fixed-mode path); use dynamic mode when it is not, accepting a still-faster-than-`malloc` amortized cost rather than a hard exhaustion failure.

## Reproduce

```bash
cmake --preset bench
cmake --build --preset bench
./build/bench/src/bench/cpp/it/d4np/memorypool/pool_vs_malloc_bench --scenario growth
```

(The growth scenario is skipped under a lock-free build, where dynamic mode is unsupported — ADR-0024 §2.)
